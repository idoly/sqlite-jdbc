= SQLite JDBC JDK 25 FFM 版
:project-version: 3.53.2.2-SNAPSHOT

image:https://img.shields.io/github/actions/workflow/status/idoly/sqlite-jdbc/ci.yml?branch=main[构建状态,link=https://github.com/idoly/sqlite-jdbc/actions/workflows/ci.yml]
image:https://img.shields.io/badge/JDK-25+-blue[JDK 25+]
image:https://img.shields.io/badge/backend-FFM-green[FFM]

本项目基于 https://github.com/xerial/sqlite-jdbc[xerial/sqlite-jdbc] 的 JDBC 层，将底层 JNI 桥迁移为 JDK 25 标准的 Foreign Function and Memory API（FFM）。项目直接调用 SQLite 公开的 `sqlite3_*` C ABI，不包含 JNI Java 桥。

IMPORTANT: xerial 官方产物坐标是 `org.xerial:sqlite-jdbc`，不包含本仓库的 FFM 修改。本项目坐标是 `io.github.idoly:sqlite-jdbc`，Java 包名是 `io.github.idoly.sqlite`，不能与 xerial JAR 混用，也不保证 `org.sqlite` 源码或二进制兼容。当前应从本仓库源码构建，或使用本仓库后续发布的明确版本。

== 要求

* JDK 25 或更高版本
* Maven 3.9 或更高版本
* 可用的 SQLite 动态库：本项目构建的纯 SQLite 库、系统 SQLite，或通过属性指定的库
* 启动 JVM 时授予 native access

类路径运行：

[source,shell]
----
java --enable-native-access=ALL-UNNAMED -cp "sqlite-jdbc.jar:slf4j-api.jar:." your.Main
----

模块路径运行：

[source,shell]
----
java --enable-native-access=io.github.idoly.sqlitejdbc \
  --module-path sqlite-jdbc.jar:slf4j-api.jar \
  --module your.module/your.Main
----

== 构建

[source,shell]
----
git clone https://github.com/idoly/sqlite-jdbc.git
cd sqlite-jdbc
mvn --batch-mode --no-transfer-progress clean package
----

主要产物：

[source,text]
----
target/sqlite-jdbc-3.53.2.2-SNAPSHOT.jar
target/sqlite-jdbc-3.53.2.2-SNAPSHOT-without-natives.jar
----

安装到本地 Maven 仓库：

[source,shell]
----
mvn install
----

== 快速使用

[source,java]
----
import java.sql.Connection;
import java.sql.DriverManager;
import java.sql.ResultSet;
import java.sql.Statement;

public class Sample {
    public static void main(String[] args) throws Exception {
        try (Connection connection = DriverManager.getConnection("jdbc:sqlite:sample.db");
                Statement statement = connection.createStatement()) {
            statement.executeUpdate("create table if not exists person(id integer, name text)");
            statement.executeUpdate("insert into person values(1, 'Alice')");
            try (ResultSet result = statement.executeQuery("select id, name from person")) {
                while (result.next()) {
                    System.out.println(result.getInt(1) + ": " + result.getString(2));
                }
            }
        }
    }
}
----

== SQLite 动态库选择

按以下顺序选择 SQLite：

. `io.github.idoly.sqlite.ffm.lib.path` 指定的完整文件路径；
. JAR 中与当前平台匹配、且导出 `sqlite3_*` 的资源；
. 系统动态库：Linux 为 `libsqlite3.so.0`，macOS 为 `libsqlite3.dylib`，Windows 为 `sqlite3`。

指定自定义库：

[source,shell]
----
java --enable-native-access=ALL-UNNAMED \
  -Dio.github.idoly.sqlite.ffm.lib.path=/absolute/path/to/libsqlite3.so \
  -cp "sqlite-jdbc.jar:slf4j-api.jar:." your.Main
----

自定义库必须与当前进程架构一致，并导出驱动使用的 SQLite 公开 API。旧 xerial JNI `libsqlitejdbc` 二进制不能用于本项目。

== JDBC 与 SQL 支持范围

本项目只支持 JDK 25+ 提供的 `java.sql` API，JDBC 规范版本为 JDBC 4.3。JDBC 没有独立的网络线协议，也没有 JDK 25 对应的 JDBC 5；驱动与进程内 SQLite 通过 C ABI 通信。

源码中的 `io.github.idoly.sqlite.internal` 是从 xerial 继承的历史类名和实现分层，不表示支持 JDBC 3。用户只应依赖标准 `java.sql`、`javax.sql`、`io.github.idoly.sqlite` 和 `io.github.idoly.sqlite.jdbc4` API；直接使用 `io.github.idoly.sqlite.internal` 不属于本项目承诺的兼容范围。后续可在不影响 JDBC 4.3 行为的独立重构中移除这层遗留。

SQL 语法由实际加载的 SQLite 动态库决定。本仓库构建基线为 SQLite 3.53.2；使用外部库时，以该库支持的 SQLite SQL、PRAGMA 和扩展能力为准。

== 已迁移能力

* Connection、Statement、PreparedStatement 和 ResultSet
* 参数绑定、BLOB、列元数据和错误码映射
* 事务、busy timeout、interrupt 和 SQLite limits
* Online Backup / Restore
* Serialize / Deserialize
* Scalar、Aggregate 和 Window Function
* Collation
* BusyHandler 和 ProgressHandler
* commit、rollback 和 update hooks
* 多 classloader
* GraalVM native-image

FFM callback 使用连接级 shared `Arena` 和强引用注册表管理。关闭连接时先注销 SQLite callback，再关闭数据库和 Arena。

== 平台说明

本项目的 Java 层要求目标平台存在可运行 JDK 25 FFM 的 JVM。Android 不满足该条件，因此不支持 Android。

仓库不保留旧 JNI 平台二进制。各平台资源由 `Build Native` GitHub Actions workflow 使用 link:Makefile[Makefile] 重新生成。生成库仅包含 SQLite amalgamation 和扩展，并直接导出 `sqlite3_*`。
